# چرا با روشن‌بودن Psiphon، خروجی هنوز Psiphon نبود (نسخه .12)

## دو مشکل جدا در یک لاگ

### ۱) ورودی زنجیره را اشتباه می‌گرفتیم (مشکل اصلی)

موتور Aether با `--psiphon` **دو** لیسنر SOCKS بالا می‌آورد:

| پورت | چیست | خروجی |
|---|---|---|
| `1819` (`--bind`) | خود تونل | WARP (خروجی Aether، **نه** Psiphon) |
| `1821` (`--psiphon-bind`) | مرحله Psiphon، که داخل همان تونل سوار است | **خروجی Psiphon** |

خود موتور هم در لاگ شما گفته بود:

```
[+] psiphon is ready; 127.0.0.1:1821 leaves through psiphon, carried by the tunnel
```

ولی اپ ما همیشه به **1819** وصل می‌شد. نتیجه: حتی وقتی Psiphon کامل بالا می‌آمد،
همه‌ی ترافیک از WARP بیرون می‌رفت. خط بعدی لاگ خودش گویاست:

```
[Aether] tunnel verified, exit ip=104.28.194.222 country=IR     ← آدرس WARP، نه Psiphon
```

### ۲) قفل دیتابیس Psiphon (کرش «stopped before it was ready»)

```
[-] psiphon: tryDatastoreOpenDB failed: psiphon.tryDatastoreOpenDB#167: timeout   (×۳)
[-] psiphon: error in init: main.(*TunnelWorker).Init#355: ... timeout
[-] psiphon: other: psiphon stopped before it was ready
```

`psiphon-tunnel-core` دیتابیس حالتش (boltdb) را با **قفل انحصاری** باز می‌کند و بعد از ~۳ ثانیه
بی‌خیال می‌شود. قفل دست **کلاینت قبلی** است و آن کلاینت با موتور نمی‌میرد: موتور را ما با
`SIGKILL` می‌کشیم (چون توقف نرم چند ثانیه طول می‌کشد) و والدِ SIGKILL‌شده هیچ cleanup‌ای اجرا نمی‌کند،
پس فرزند Psiphon زنده می‌ماند و قفل را نگه می‌دارد. الگوی لاگ شما هم همین است:

- شروع اول (BE) → timeout
- بعدی (خودکار) → **کار کرد**
- تغییر به GB (ری‌استارت موتور) → دوباره timeout

## چه چیزی عوض شد

1. **`AetherEntry`** (فایل تازه): یک منبع واحد برای «پورت ورودی زنجیره».
   - TCP → `1821` وقتی مرحله Psiphon زنده است، وگرنه `1819`.
   - **UDP همیشه روی `1819`**: پروکسی Psiphon فقط TCP را حمل می‌کند (UDP ASSOCIATE ندارد)؛
     اگر UDP را هم به 1821 می‌بردیم، DNS کلاً می‌مُرد. UDP همان‌طور داخل تونل می‌ماند و فقط
     از خروجی خود تونل بیرون می‌رود، نه از خروجی Psiphon.
   - `AetherUpstream`، رله TCP، هدف hev، پورت زنجیره Xray و probe سرویس همه از این منبع می‌خوانند.
2. **دروازه‌ی واقعی برای Psiphon:** اپ قبلاً به‌محض باز شدن `1819` می‌گفت «آماده».
   حالا با روشن‌بودن مرحله، تا **باز شدن `1821`** صبر می‌کند (بودجه `AETHER_PSIPHON_READY_SECS=300`)
   و اگر موتور بمیرد سریع تسلیم می‌شود. فقط بعد از آن `trafficReady` می‌شود و ترافیک به زنجیره می‌رود.
3. **تأیید خروجی از پورت درست:** بررسی IP حالا از `1821` انجام می‌شود، پس عددی که در UI می‌بینید
   واقعاً خروجی Psiphon است (اگر IR/WARP دیدید یعنی مرحله نیست).
4. **دیتابیس تازه برای هر لانچ:** `AETHER_PSIPHON_DIR = files/psiphon/<launchId>`.
   با این کار تصادم قفل **از اساس** ممکن نیست. دایرکتوری‌های قدیمی بعد از هر لانچ پاک می‌شوند.
5. **کشتن کلاینت‌های سرگردان:** قبل از هر استارت، پروسه‌های `libpsiphon.so` متعلق به همین اپ
   (که از لانچ قبلی مانده‌اند) کشته می‌شوند.
6. `AETHER_PSIPHON_BIND` صریح ست می‌شود (`127.0.0.1:1821`) تا هرگز با پیش‌فرض موتور فرق نکند.
7. **۶ تست تازه** برای همین منطق (جمعاً **۱۵۰ تست، ۰ خطا**).

## چه چیزی در لاگ نسخه .12 باید ببینید

```
[Aether] psiphon stage live on 127.0.0.1:1821 - TCP now leaves through Psiphon (UDP stays on 1819)
[Aether] tunnel verified, exit ip=<آی‌پی Psiphon> country=<کشور Psiphon>
```

اگر همان `exit ip=104.28.194.222 country=IR` را دیدید، یعنی Psiphon بالا نیامده و ترافیک از تونل رفته؛
در آن حالت حالا پیام خطای فارسی روی صفحه می‌آید و اتصال «موفق» اعلام نمی‌شود.

## محدودیت‌های صادقانه

- UDP از خروجی Psiphon نمی‌رود (Psiphon فقط TCP دارد). یعنی DNS و QUIC از WARP می‌روند و TCP از Psiphon.
  این تصمیم عمدی است؛ گزینه‌ی «UDP هم از Psiphon» نیازمند udpgw و یک لایه‌ی اضافه است (کاری که خود
  پروژه‌ی مرجع در `PsiphonSocksFront` کرده) و در این نسخه نیست.
- هنوز روی گوشی واقعی توسط من تأیید نشده؛ سندباکس شبکه ندارد.
